End-to-end architecture and code review

Not ready for live activation or whole integration acceptance. The inspected ownership and state-machine design is coherent as a conditional, fail-closed runtime. Eight concrete gaps still need closure. The next step is to finish four ownership/interface contracts, then implement and qualify the real workflow.

1. Architecture review

Protected host code owns authorization and persistence. Candidate code receives only its bounded workload access. Negative actors can contain work but cannot start it or authorize reuse. A sampled observation does not establish continuous runtime truth.

A1 · Authority stays outside candidate code

Enrollment and issue text supply bounded data. Protected Store transactions own current assignments, limits and commitments. Runtime facts still require authenticated producers.

Coherent source design; actual producer integration open.

A2 · Positive and negative ownership are separate

The positive process drives work. The observer owns only containment and survives positive loss. The proposed earlier keeper covers preparation and observer construction.

Observer primitive exists; whole keeper/recovery contract unfinished.

A3 · One original time budget

Native T0 precedes per-attempt input reads; later samples cannot renew it. Setup, wire, positive, containment and final bounds retain their distinct purposes.

Preserve original15/44/60/65/90/120 and separate150ms requirements; current actual startup/workload evidence absent.

A4 · Immutable input and private writable state differ

Execution/assets are externally selected immutable generations. Run state and Store are separate private writable objects. Policy hashes bind the declaration, not external trust.

Retention checks exist; actual startup/package closure open.

A5 · Commitment, result, delivery and capacity are distinct

Commit before send; uncertain sends are consumed. A queued reply is not successful delivery. A known command result is not resource release.

Source transitions enforce the distinctions; real effect/recovery adapters unqualified.

A6 · Conditional compatibility is allowed

Exact original membership plus fail-closed containment can support a successful qualified run. Unknown resource classes reject.

No universal no-churn or scheduling theorem is introduced; actual success still required.

A7 · Scope stays local and evidence based

The target is this WSL host. Additional profiles, parallel modes and convenience features can wait. Existing advisory/source-only components cannot be relabeled as a live runner.

First-release runtime gates remain mandatory; D01–D07 are not declared complete.

2. Findings that block completion

These are implementation and evidence gaps. They do not justify relaxing deadlines, containment, consumed-attempt history or original membership. No new universal scheduler theorem is required.

P1Known missing integration

R1 · No whole-lifecycle keeper

Native main prepares directly. Sequential deadline checks cannot intervene while a syscall or helper blocks. A keeper must start from the original pre-input T0, cover the positive process and acquired runtime target, and preserve the original cutoffs.

Close with: Implement one controlled fork ownership transition; integrate both consumed intent/acquisition phases.

automation/native/runtime_stage0_qualification_main.c:15

P1Additional integration finding

R2 · Native resource recovery has no complete handoff

Loop, DM and mount effects outlive descriptor closure. Native preparation retains in-memory failure information and a write-ahead journal, but main exits125 without handing a complete recovery owner its unresolved inventory. Cgroup containment alone cannot reconcile those resources.

Close with: Define how the keeper locates the consumed journal, preserves late/unresolved effects and authenticates exact resources for recovery without replay or adoption. Retention/UNKNOWN is permitted; cleanup success cannot be assumed.

automation/native/runtime_stage0_preparer.c:235; automation/native/runtime_stage0_qualification_main.c:28

P1Additional integration finding

R3 · Observer construction needs independent protection

The child can fail during clock reset, descriptor pruning or prepared-record construction before entering the consuming Observer factory. Parent recovery construction also follows the fork. The factory cannot contain an interval before it has been called.

Close with: Require acknowledged keeper acquisition before prefork, and test parent loss combined with each pre-factory child failure.

automation/control_runtime_bootstrap.py:139

P1Known missing implementation

R4 · The private entry and actual task executor are missing

Native launch imports automation.control_runtime_qualification, which is absent. RootEntry returns STORE_READY_ONLY. Controller, bootstrap, startup, workspace and supervisor operational constructors are deliberately disabled. The retained-start consumer alone does not execute a bound session or rnr_command.

Close with: Wire the actual create/start/configuration/freeze/consumption path, then real session ownership, isolated workspace/command execution and result/recovery adapters. Include all sources in the immutable layout.

automation/native/runtime_stage0_launch.c:299; automation/control_runtime_root_entry.py:171; automation/control.py:74

P1Known incomplete profile

R5 · Actual Codex resource admission is incomplete

Frozen admission accepts a narrower descriptor and mapping profile than the selected runtime requires. The metadata-only inotify parser does not admit watches. Sockets, private database/lock files and mapped backing objects still need concrete predicates and pre-exec confinement. A selected UID is not proof of exclusive identity ownership.

Close with: Close private filesystem/socket/identity invariants and define bounded file/watch/mapping predicates. Preserve KCMP, exact original membership and fail-closed rejection.

automation/control_runtime_frozen.py:586; automation/control_runtime_frozen.py:601; automation/control_runtime_frozen.py:669

P1Known audit gap

R6 · Startup trust is not established by selectors

Project and payload selectors produce metadata. They do not prove that the installed binary, interpreter, extensions, ELF/data dependencies, helpers, configuration and startup initialization use the intended immutable closure. Historical resolver failures remain inconclusive.

Close with: Freeze the integrated build and audit current actual executable/import/configuration closure, initialization, stdio and descriptor budgets before invocation.

automation/control_runtime_project_layout.py:171; automation/control_runtime_payload.py:1; automation/control_runtime_execution_root.py:1

The source suite includes simulated workload/frozen boundaries. No actual native-preparer → Store → bound agent session → command → recovery qualification has run for the current implementation. Passing source tests cannot establish that journey.

Close with: After prerequisites: run one separately identified actual success, blocked/late/failing operation and recovery matrix under the original contract; preserve UNKNOWN and consumed history.

5. Ordered path to finishing the unfinished work

  1. Close the keeper interfaces first. Specify the controlled fork/clock transfer, pre-create intent and post-create acquisition, native journal/recovery ownership, and normal/failure FD peaks. The keeper must already protect observer construction.
  2. Implement and review the whole keeper/recovery path. Check blocked operations, parent loss, partial observer construction, lost/late ACKs and cutoff expiry without replay or deadline renewal.
  3. Complete the actual runtime profile and workload path. Authenticate private filesystem/socket/identity confinement; implement bounded resource predicates; connect real private entry, session binding, workspace and rnr_command execution.
  4. Freeze and audit the actual integrated artifact. Include current source, interpreter, stdlib/extensions, ELF/data dependencies, native helpers, configuration and initialization. Verify startup/descriptor constraints against the selected build.
  5. Run actual success, failure and recovery qualification. Preserve exact artifact/environment, original clocks/caps and consumed attempt history. UNKNOWN retains holds; confirmed results require independent evidence and review.
  6. Activate only the qualified local mode. Provide its real start/inspect/stop/recovery path and release evidence. Defer additional profiles, parallel modes and convenience features. Do not represent D01–D07 or unrelated deployment as complete.
